# Functional module examples

These workflows use the real public Enbox API. Their manifests, paths and payloads
are typechecked during the package build and exercised against a real DWN in tests.
They are application data flows, not UI scaffolds.

| Workflow | Files | Contract |
| --- | --- | --- |
| Household | [household.ts](household.ts), [household-contexts.ts](household-contexts.ts) | One Collaboration space owns memberships; shopping, meals and tasks own their attached records. |
| Notebook | [notebook.ts](notebook.ts) | The canonical notesd notebook/page hierarchy and CRDT frames. Realtime is an optional extension with the same page roles. |
| Portfolio | [portfolio.ts](portfolio.ts) | Financial Accounts owns account identity; positions attach independently of the optional Transactions ledger. Watchlists describe interest. |

Register the appropriate manifest when connecting, then pass the authenticated
`Enbox` session to a workflow. Applications using the same published module URI,
path and record ID read and update the same data; the tests use independent
bindings to verify this.

For managed household sharing, install `@enbox/contexts` and register
`managedHouseholdApplication`. Its `HouseholdContextsModule` is generated by the
existing companion factory. Select feature modules explicitly:

```ts
import { bindContexts } from '@enbox/contexts';
import { CollaborationModule } from '@enbox/modules/collaboration';
import { GroceriesModule } from '@enbox/modules/groceries';
import { defineContextModule } from '@enbox/contexts';

const companion = defineContextModule(CollaborationModule);
const contexts = bindContexts(enbox, companion).withModules({
  groceries: GroceriesModule,
});
const household = await contexts.open('space', spaceContextId);
await household.members.set(memberDid, { role: 'space/editor', data: {} });
await household.invite(memberDid, { preview: { title: 'Our household' } });
```

The owner issues memberships. Context follow/invitation behavior and key delivery
come from the existing SDK and companion. Viewer assignments are scoped to this
space; personal reminders remain in the recipient's own private state. Space
admins may moderate explicitly authorized feature records, but cannot assign
memberships or prune the space. The owner can prune the entire physical subtree.

Independent evidence, such as identity scans or receipt files, should remain
linked records when it must survive deletion of a shared context. References do
not grant access, and structural attachment does not cross tenant ownership.

The portfolio fixture contains illustrative supplied observations, not market
prices or investment advice. Production capture must resolve the intended account
and instrument before recording ownership. The notebook example requires the
optional `@enbox/crdt` application dependency to encode and materialize text.
