`@enbox/api` is the main package developers use to interact with the Enbox network. It provides a type-safe, protocol-scoped API for creating, reading, querying, counting, updating, and deleting records stored in Decentralized Web Nodes (DWNs).

## Installation

```bash
bun add @enbox/api
```

## Core concepts

### Enbox

The `Enbox` class is the entry point. You create an instance with `Enbox.connect()`:

```ts
import { Enbox } from '@enbox/api';

const { enbox, session } = await Enbox.connect({ createIdentity: true });
```

`Enbox.connect()` creates the default auth/session lifecycle and returns the `Enbox` API, active session, and underlying auth manager. If you manage sessions yourself with `@enbox/auth` or `@enbox/agent`, pass the session directly:

```ts
const enbox = Enbox.fromSession(session);
```

For raw agent integration, use the public constructor: `new Enbox({ agent, connectedDid })`.

The `Enbox` instance exposes:

| Property / Method | Description |
|---|---|
| `enbox.using(protocol)` | Returns a `TypedEnbox` scoped to a protocol |
| `enbox.did` | DID API — create and resolve DIDs |
| `enbox.vc` | Verifiable Credentials API |
| `enbox.agent` | The underlying `EnboxAgent` |
| `enbox.getConnectionStatus()` | Reports active, expiring, expired, or revoked delegated grants |
| `enbox.refresh({ protocols })` | Requests fresh grants for the same delegate on instances returned by `Enbox.connect()` |
| `enbox.disconnect()` | Stops sync and clears cached instances |

There is **no public `dwn` property** on the `Enbox` instance. All DWN access goes through `enbox.using(protocol)`.

## Browser imports

Browser apps can import `@enbox/api` directly, but most apps should use
`@enbox/browser` because it re-exports the API and adds browser connect helpers:

```ts
import { BrowserConnectHandler, Enbox, defineProtocol, recordCodecs } from '@enbox/browser';
```

The `@enbox/api` root export also has a browser condition for bundlers that
consume it directly. See [Browser & bundlers](/docs/guides/browser-bundlers) for
service-worker and storage details.

### defineProtocol

`defineProtocol()` pairs a protocol definition with the runtime codec for each record type:

```ts
import { defineProtocol, recordCodecs } from '@enbox/api';

interface TaskData {
  title: string;
  done: boolean;
}

const TaskProtocol = defineProtocol({
  protocol:  'https://example.com/tasks',
  published: true,
  types: {
    task: {
      schema:      'https://example.com/schemas/task',
      dataFormats: ['application/json'],
    },
  },
  structure: {
    task: {
      $tags: {
        done: { type: 'boolean' },
      },
    },
  },
}, {
  task: recordCodecs.json<TaskData>(),
});
```

The same codec encodes writes and decodes `record.value()`. Protocol declarations therefore carry their runtime behavior and TypeScript value types in one place.

### TypedEnbox

`TypedEnbox` is the **primary developer interface**. You get one by calling `enbox.using(protocol)`:

```ts
const tasks = enbox.using(TaskProtocol);
```

Instances are cached by typed-protocol object identity — calling `using()` repeatedly with the same exported protocol constant returns the same instance.

`TypedEnbox` **auto-configures** the protocol on the first record operation — it queries the local DWN for an existing installation and installs one if needed. You can start using records immediately without any setup step.

If you need explicit control (for example, to check the status code or to pre-install before any reads), call `configure()` manually:

```ts
const { status } = await tasks.configure();
// status.code: 200 (already installed) or 202 (newly installed)
```

### TypedEnbox.records

All record methods auto-inject `protocol`, `protocolPath`, and `schema` — you only provide the path and your data:

Typed record methods return application values instead of raw DWN response
envelopes. `create()` returns a `Record`, `query()` returns a `RecordPage`,
`count()` returns a number, and `read()` returns a `Record` or `undefined`.
`Record.update()` and `patch()` return the same updated handle; successful
delete, store, import, and send operations resolve without a value. A
non-success DWN status throws `DwnResponseError` (except a missing read, which
returns `undefined`):

```ts
import { DwnResponseError } from '@enbox/api';

try {
  await tasks.records.delete('task', { recordId: taskId });
} catch (error) {
  if (error instanceof DwnResponseError) {
    console.error(error.status.code, error.status.errorCode, error.status.detail);
  }
}
```

Use the low-level DWN API when you need exact response envelopes and status
codes.

#### create

```ts
const record = await tasks.records.create('task', {
  data : { title: 'Buy milk', done: false },
  tags : { done: false },
});
// record is Record<TaskData>
```

Create options:

| Field | Type | Description |
|---|---|---|
| `data` | `T` (type-checked) | The record payload |
| `parentContextId` | `string?` | Link to a parent record's `contextId` |
| `published` | `boolean?` | Whether the record is publicly readable |
| `recipient` | `string?` | DID of the intended recipient |
| `protocolRole` | `string?` | Role for permission-scoped writes |
| `tags` | `Record<string, ...>?` | Indexed key-value metadata |
| `store` | `boolean?` | Persist locally (default `true`) |

#### query

```ts
const page = await tasks.records.query('task');

for (const r of page.records) {
  const data = await r.value(); // TaskData
  console.log(data.title, data.done);
}
```

Query with filters, sorting, and pagination:

```ts
import { DateSort } from '@enbox/dwn-sdk-js';

const selection = {
  filter: { tags: { done: false } },
  dateSort: DateSort.CreatedDescending,
  pagination: { limit: 25 },
};

const page = await tasks.records.query('task', selection);

// Fetch next page
if (page.cursor) {
  const { records: next } = await tasks.records.query('task', {
    ...selection,
    pagination: { ...selection.pagination, cursor: page.cursor },
  });
}
```

Eagerly decode a bounded page when application code needs values immediately:

```ts
const { records } = await tasks.records.query('task', {
  materialize: true,
  pagination: { limit: 25 },
});

for (const item of records) {
  console.log(item.value.title);
  await item.record.delete();
}
```

Each materialized item contains exactly `{ record, value }`. A `children`
property is added only when the request explicitly selects child paths; each
selected child has the same two-field `{ record, value }` shape.

For a direct child whose protocol rule declares `$recordLimit: { max: 1 }`,
`materialize: { children: [...] }` fetches that child path once for the whole
parent page. Each selected key is present and is `undefined` when that parent
has no visible child. Query and observe publish the same shape.
Materialization decodes eagerly and may buffer codec output; omit it for large
payloads and consume `record.data.stream()` instead.

#### observe

`observe()` is the normal reactive collection primitive. It installs a local
wake subscription before its first query, then rematerializes that same query
after matching changes. The required limit makes retained collection size
explicit:

```ts
const view = await tasks.records.observe('task', {
  filter: { tags: { done: false } },
  dateSort: DateSort.CreatedDescending,
  pagination: { limit: 25 },
});

const unsubscribe = view.subscribe((snapshot) => {
  // state is loading | ready | stale | error
  renderTasks(snapshot.records, snapshot.state, snapshot.hasMore);
});

// getSnapshot() is useful for the initial render and framework adapters.
const initial = view.getSnapshot();
renderTasks(initial.records, initial.state, initial.hasMore);

unsubscribe();
await view.close();
```

Observed views are local-replica resources: they do not accept `from`.
Subscription payloads never mutate collection truth directly, and record data
continues to decrypt lazily through each `Record<T>`. Views created through
`enbox.using()` publish one terminal `error` snapshot and close when that Enbox
session ends. After automatic grant refresh, `ConnectionStore` publishes a
replacement `enbox`; direct `Enbox.fromSession()` consumers recreate resources
from the replacement `AuthManager.session` announced by `session-start`.

`loading` means a configured replicated source has not completed its required
pull. An empty `ready` snapshot is therefore an authoritative empty result.
After the first ready snapshot, an offline or catching-up source reports
`stale`; successful local materializations still update its records so offline
writes remain visible. Query, authorization, or terminal sync failures report
`error` while retaining the latest successful records. `hasMore` is always a
boolean and is false until the first query completes.

Snapshots and their record arrays are immutable. A `Record<T>` represents
the queried version until the caller explicitly invokes that handle's regular
`update()` or `delete()` method; its data is still read lazily.

#### set

`set()` is the one create-or-replace operation. It is available only on paths
whose protocol rule declares `$recordLimit: { max: 1 }`:

```ts
const title = await library.records.set('book/title', {
  data: 'The Left Hand of Darkness',
  within: book.contextId,
});
```

Nested singleton paths require their direct-parent context; root singletons do
not accept one. This operation targets only the connected tenant's local replica
and does not accept remote targets or protocol-role invocation. Because `set()`
first selects the current occupant, callers need both read and write
authorization; a delegate's Records.Read grant must cover RecordsQuery.
Concurrent first creates retain the DWN's normal deterministic visibility
semantics rather than adding a lock.

#### count

`count()` accepts the same typed selection as `query()` and counts the full
authorized population before pagination. This makes one query reusable
for a page and its total:

```ts
const selection = {
  filter: { tags: { done: false } },
  pagination: { limit: 25 },
};

const page = await tasks.records.query('task', selection);
const count = await tasks.records.count('task', selection);
// page.records.length <= 25; count covers every matching task
```

#### read

Read a specific record by ID:

```ts
const record = await tasks.records.read('task', {
  filter: { recordId: taskId },
});

if (record === undefined) {
  throw new Error('Task not found');
}

const data = await record.value(); // TaskData
```

Read from a remote DWN:

```ts
const remote = await tasks.records.read('task', {
  from: 'did:dht:alice...',
  filter: { recordId: taskId },
});
```

#### delete

Delete via the `TypedEnbox` API:

```ts
await tasks.records.delete('task', {
  recordId: record.id,
});
```

Or delete via the record instance:

```ts
await record.delete();
```

## Record&lt;T&gt;

`Record<T>` is the one mutable record class. `TypedEnbox` returns the same
runtime `Record` used by the lower-level DWN API while carrying the selected
protocol payload type as `T`; there is no second wrapper or `rawRecord` escape
hatch.

### Data accessors

```ts
const task = await record.value();        // Promise<TaskData>
const raw  = await record.data.text();    // Promise<string>
const blob = await record.data.blob();    // Promise<Blob>
const bytes = await record.data.bytes();  // Promise<Uint8Array>
const stream = await record.data.stream(); // Promise<ReadableStream>
```

When consuming multiple representations, capture `const data = record.data`.
Convenience calls on that accessor cache up to 10 MB without re-reading from
the DWN. Direct `stream()` calls remain streaming and are not eagerly buffered.

### Metadata

| Property | Type | Description |
|---|---|---|
| `record.id` | `string` | Unique, stable record ID |
| `record.contextId` | `string?` | Hierarchical grouping ID |
| `record.dateCreated` | `string` | ISO 8601 creation timestamp (immutable) |
| `record.timestamp` | `string` | ISO 8601 timestamp of last mutation |
| `record.author` | `string` | DID of the current message signer |
| `record.creator` | `string` | DID of the original author |
| `record.protocol` | `string?` | Protocol URI |
| `record.protocolPath` | `string?` | Path within the protocol structure |
| `record.schema` | `string?` | Schema URI from the protocol type |
| `record.dataFormat` | `string?` | MIME type of the payload |
| `record.dataSize` | `number?` | Payload size in bytes |
| `record.tags` | `object?` | Indexed key-value metadata |
| `record.published` | `boolean?` | Whether publicly readable |
| `record.deleted` | `boolean` | Whether the record has been deleted |
| `record.parentId` | `string?` | Parent record ID |
| `record.recipient` | `string?` | Recipient DID |

### Mutation methods

#### update

```ts
const updated = await record.update({
  data: { title: 'Buy oat milk', done: false },  // complete TaskData
  tags: { priority: 'high' },
});
```

`update({ data })` replaces the payload wholesale, so `data` must contain the
complete `T`. Omitting a field removes it from the stored payload. Both the
returned value and the original variable reference the same updated `Record`.

#### patch

Use `patch()` when only part of a JSON object should change:

```ts
const updated = await record.patch({
  done: true,
});
```

`patch()` reads the current JSON object, performs a shallow merge, and writes
the complete merged payload. Nested objects are replaced rather than
deep-merged, `undefined` leaves a field unchanged, and `null` deletes an
optional field. Set a required nullable field to `null` with a complete
`update()` instead. Like any read-merge-write operation, `patch()` can overwrite
a concurrent update that lands between its read and write.

#### delete

```ts
await record.delete();
```

Delete with options:

```ts
await record.delete({ prune: true });  // also delete child records
```

### Lifecycle methods

| Method | Description |
|---|---|
| `record.send(target?)` | Push the record to a remote DWN. Defaults to your own remote DWN. |
| `record.store(importRecord?)` | Persist to local DWN (for records created with `store: false`) |
| `record.import(store?)` | Re-sign under your identity and optionally store (for importing others' records) |
| `record.rawMessage` | Exact `RecordsWrite` or `RecordsDelete` message backing the current record state |

## Anonymous queries

`Enbox.anonymous()` creates a lightweight, read-only instance for querying **published** records without authentication:

```ts
const { dwn } = Enbox.anonymous();

const { records } = await dwn.records.query({
  from: 'did:dht:alice...',
  filter: {
    protocol: 'https://social.example/posts',
    protocolPath: 'post',
  },
});

for (const record of records) {
  console.log(record.id, await record.data.text());
}
```

No identity, vault, password, or signing keys are required. Only unsigned (anonymous) DWN messages are supported — you can query and read, but not write.

## Hierarchical records

Protocols can define nested structures. Use `parentContextId` to create child records:

```ts
const NotebookProtocol = defineProtocol({
  protocol:  'https://example.com/notebooks',
  published: true,
  types: {
    notebook: {
      schema:      'https://example.com/schemas/notebook',
      dataFormats: ['application/json'],
    },
    page: {
      schema:      'https://example.com/schemas/page',
      dataFormats: ['application/json'],
    },
  },
  structure: {
    notebook: {
      page: {},
    },
  },
}, {
  notebook: recordCodecs.json<{ name: string }>(),
  page: recordCodecs.json<{ title: string; body: string }>(),
});

const notebooks = enbox.using(NotebookProtocol);

// Create a parent
const notebook = await notebooks.records.create('notebook', {
  data: { name: 'Travel Notes' },
});

// Create a child under the parent
const page = await notebooks.records.create('notebook/page', {
  data: { title: 'Day 1', body: 'Arrived in Tokyo...' },
  parentContextId: notebook.contextId,
});

// Query children of a specific parent
const { records: pages } = await notebooks.records.query('notebook/page', {
  within: notebook.contextId,
});
```

## Disconnecting

When the user signs out, call `disconnect()` for the full sign-out flow:

```ts
await enbox.disconnect();
```

When `Enbox.connect()` built the agent itself (i.e. you did not pass an `agent` option), `disconnect()` does three things:

1. **Stop sync** — halt the background DWN sync engine.
2. **Sign out** — send delegate-grant revocations to the connected DWN, clear session restore markers (so the next `Enbox.connect()` does not silently restore the signed-out session), and clear the in-memory delegate decryption key cache.
3. **Release resources** — lock the vault, close the sync engine, and close the storage adapter.

If you passed a pre-built `agent` to `Enbox.connect({ agent })`, only step 1 runs — your agent and its `AuthManager` keep their lifecycle, and you are responsible for calling `auth.disconnect()` and `auth.shutdown()` on your own handle when you are done:

```ts
const auth = await AuthManager.create({ /* ... */ });
const session = await auth.connectVault({ createIdentity: true });
const enbox = Enbox.fromSession(session);

// ... user uses the app ...

await enbox.disconnect();   // stops sync + clears typed-enbox cache only
await auth.disconnect();    // sign out: revoke grants, clear markers
await auth.shutdown();      // release: lock vault, close storage
```

After calling `disconnect()`, the `Enbox` instance should not be reused. Create a new one with `Enbox.connect()` for the next session.
